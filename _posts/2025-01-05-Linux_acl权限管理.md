### Linux ACL 权限详解：访问控制列表

传统 Linux 权限只能对“所有者、所属组、其他人”三类设置权限。当你需要给**某个具体用户**或**某个具体组**单独设置权限时，就需要用到 ACL（Access Control List，访问控制列表）。

ACL 的作用在于让权限管理更加灵活和精细。

---

### ACL 基本概念

ACL 允许你在文件或目录上添加额外的权限规则，而不需要修改原有所有者和组。  
使用 ACL 后，用 `ls -l` 查看文件时，权限后面会出现 `+` 号，表示该文件启用了 ACL。

---

### 查看 ACL

```bash
# 查看某个文件或目录的 ACL 信息
getfacl 文件名或目录名
```

**解释**：这条命令会显示传统权限 + 所有 ACL 额外规则，非常清晰。

---

### 给具体用户设置权限（最常用）

```bash
# 示例1：给用户 zhangsan 读写权限
setfacl -m u:zhangsan:rw important.log

# 示例2：给用户lisi 完整权限（读写执行）
setfacl -m u:lisi:rwx /app/script.sh
```

**解释**：即使 zhangsan 不是文件所有者，也能获得 rw 权限。这在团队协作中非常实用。

---

### 给具体组设置权限

```bash
# 示例：给 developers 组读执行权限
setfacl -m g:developers:rx /project/web

# 递归给整个目录及其子文件设置
setfacl -R -m g:developers:rx /project
```

**解释**：这样整个开发团队都能读取项目文件，而不需要把他们都加到同一个组里。

---

### 网站部署常见场景

```bash
# 给部署用户完整权限，给 web 组只读权限
setfacl -m u:deploy:rwx /var/www/html
setfacl -m g:www-data:rx /var/www/html
```

**解释**：部署用户可以上传文件，web 服务器只能读取，这样权限划分更安全。

---

### 默认 ACL（新文件自动继承）

```bash
# 设置目录的默认 ACL，新建的文件会自动应用这些权限
setfacl -m d:u:zhangsan:rwx /shared/project
```

**解释**：团队成员在共享目录中新建文件时，会自动获得 zhangsan 的权限，省去了每次手动设置的麻烦。

---

### 删除 ACL 规则

```bash
# 删除某个用户的 ACL
setfacl -x u:zhangsan 文件名

# 清空文件的所有 ACL
setfacl -b 文件名
```

---

### 实用技巧

```bash
# 查看目录下所有带 ACL 的文件
getfacl -R /目录路径 2>/dev/null | grep -E "file:|user:"

# 同时设置 mask（控制 ACL 最大权限）
setfacl -m m:rwx 文件名
```

---

### 注意事项

- __ACL 是对传统权限的补充，不会覆盖原有 owner/group 权限。__ __ACL的匹配先于基础权限，一旦匹配就退出权限比对__
- __ACL 的 mask（ACL 掩码）：mask 是文件的一个 ACL 属性，一份文件只有唯一一个 mask，不存在 “每个人单独的 mask”。mask也会对传统权限的所属组生效，取两者的交集__
- __执行 setfacl -m u/g:xxx 添加或修改自定义用户 / 组 ACL 时，系统会自动重算 mask 为当前所有自定义条目的最大权限（并集）；手动 setfacl -m m:rx 可以强制固定 mask，但仍会刷新__
- __自定义 ACL 实际权限 = ACL 配置权限 按位与 mask 权限__

---

### 小结

ACL 特别适合以下场景：
- 多人协作但不想频繁改组
- 需要给特定用户特殊权限
- 权限控制要求较高的生产环境
