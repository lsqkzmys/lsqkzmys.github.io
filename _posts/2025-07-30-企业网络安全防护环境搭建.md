这次的项目是**从零搭一套小型企业网的安全防护体系**：业务藏在防火墙后面，出口先过 WAF，旁边挂蜜罐，运维走堡垒机，外部接入走 VPN + ACL 白名单。

**整体要求（四步）**：① 划分 VLAN + DHCP + 防火墙策略；② 部署堡垒机（JumpServer）、WAF（雷池）、蜜罐（HFish）和 Web 业务；③ 做端口映射（pfSense 双层映射）和资产接入；④ 用 OpenVPN + 防火墙 ACL 控制外部访问。

> 拓扑要点：pfSense 防火墙的 WAN 口是 10.10.1.56，内网是 192.168 网段（VLAN 10 / 20 / 40）。10.10.1.148 是额外加的管理网卡，方便本机访问。

### **<span style="color:#3498db">一、VLAN、DHCP 与防火墙策略</span>**

在 pfSense 上划 VLAN：指定父接口（lan）和 802.1Q 的 VLAN 标识（这里建 **VLAN 40**），一个 VLAN 一条，10/20/40 同理。VLAN 的意思就是**把一个物理网络切成几个互相隔离的虚拟局域网**，不同 VLAN 默认不能互通：

![mm](/assets/img/2025-07-30-16-00-01.png)

建完 VLAN 要给每个 VLAN 分配接口并启用（父接口下的 VLAN 接口才是可配 IP 的"三层口"）：

![mm](/assets/img/2025-07-30-16-01-15.png)

防火墙策略：**默认拒绝、按需放行**——给各 VLAN 写好允许出网/互访的规则：

![mm](/assets/img/2025-07-30-16-24-05.png)

开启 DHCP 服务，让各网段的终端自动拿 IP：

![mm](/assets/img/2025-07-30-16-26-44.png)

### **<span style="color:#3498db">二、业务与安全设备</span>**

给虚拟机加网卡并改网卡配置文件（走 VLAN 的机器要手工配好对应网段）：

![mm](/assets/img/2025-07-30-16-32-23.png)
![mm](/assets/img/2025-07-30-16-36-02.png)

**堡垒机（JumpServer）**——所有运维登录的统一入口，运维人员不直接碰业务机，先登堡垒机、再由堡垒机代填账号连资产，全程可审计：

```bash
./jmsctl.sh install && ./jmsctl.sh start   # 默认端口80，默认账密 admin/ChangeMe
```

![mm](/assets/img/2025-07-30-16-55-54.png)

**雷池（WAF）**——挡在 Web 业务前面的应用防火墙，SQL 注入、XSS 这类攻击在它这层先被拦：

```bash
sudo bash -c "$(curl -fsSL https://waf-ce.chaitin.cn/release/latest/setup.sh)"   # 默认端口9443
```

![mm](/assets/img/2025-07-30-16-58-40.png)

**HFish（蜜罐）**——故意摆的"假服务"，谁碰它就说明谁在扫描/入侵，用来做告警和诱捕：

```bash
bash <(curl -sS -L https://hfish.net/webinstall.sh)   # 默认端口4433，账密 admin/HFish2021
```

![mm](/assets/img/2025-07-30-17-02-53.png)

最后把 Web 业务服务起起来，等待被映射出去。

### **<span style="color:#3498db">三、映射与资产接入</span>**

**雷池映射**：防护应用 → 添加应用 → 上游服务器填 Web 业务的 IP 和端口（删除 443 因为需要证书），雷池就开始代理这个业务：

![mm](/assets/img/2025-07-30-17-11-05.png)

**pfSense 端口转发（双层映射）**：WAN 口 8090 → 重定向到 **雷池** 的 192.168.10.11:8090。注意链路是**两层**的——外网访问先到防火墙，防火墙转给雷池，雷池再转发给真正的业务：

![mm](/assets/img/2025-07-30-17-17-38.png)

**出站规则**：内网没配默认路由，回程数据如果被"别的网关"转回去，**源 IP 就不对了，客户端会直接把包丢掉**——所以必须配出站 NAT，让回程流量从原路出去：

![mm](/assets/img/2025-07-30-17-25-50.png)

**堡垒机分配资产**：控制台 → 资产列表 → 创建 Linux 资产，填能登录业务的账号，之后就能在堡垒机里开终端（web 终端）操作业务机：

![mm](/assets/img/2025-07-30-17-34-10.png)

**蜜罐端口映射**：映射的端口**必须是蜜罐自己监听的端口**，否则超时不生效；映射成功后从外网能访问到"假服务"：

![mm](/assets/img/2025-07-30-19-28-27.png)

### **<span style="color:#3498db">四、OpenVPN + 防火墙 ACL</span>**

装 OpenVPN 插件，然后向导建服务。两个关键设置：

1. **IPv4 隧道网络**：VPN 自己的网段（如 `10.0.8.0/24`，不能和现有网段冲突）；
2. **IPv4 Local Network**：相当于**推送路由**——填进去的网段才会被丢进隧道。这里只填 `192.168.20.0/24`，**意味着只有 20 网段能通过 VPN 访问**，10/40 没有路由、根本进不了隧道。

![mm](/assets/img/2025-07-30-09-50-42.png)

给用户勾选证书（OpenVPN 靠证书认证），导出 `.ovpn` 客户端配置：

![mm](/assets/img/2025-07-30-09-56-01.png)

Kali 上用这份配置连：

```bash
sudo openvpn client.ovpn    # 输入证书用户名密码，看到 Initialization Sequence Completed 就是成功了
```

![mm](/assets/img/2025-07-30-10-08-43.png)

最后给 20 网段加回程路由（改完 `sudo netplan apply`），从 VPN 里访问业务成功：

![mm](/assets/img/2025-07-30-10-22-16.png)

### **<span style="color:#3498db">复盘</span>**

这套环境里每个组件都在补一个洞：**VLAN** 管二层隔离、**防火墙策略/出站 NAT** 管三层通路、**WAF** 拦应用层攻击、**堡垒机**收口运维入口、**蜜罐**做诱捕告警、**VPN + ACL** 控制外网接入——一个"能上网"的企业网和一个"安全"的企业网，差距就在这些层上。
